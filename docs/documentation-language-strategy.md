# 文档语言策略

## 目标

`action-guard` 当前阶段以中文读者为主要受众，因此仓库文档默认采用“中文主叙述 + 英文代码标识”的策略，而不是整仓双语并行维护。

这样做的目标是：

- 降低维护成本，避免中文和英文两套文档长期漂移
- 保持接入文档、设计文档和治理文档的表达一致
- 让模块名、配置名、API 名称继续与代码实现保持精确对应

## 当前统一规则

### 1. 主语言

公开文档默认使用中文书写，包括：

- 根目录 `README.md`
- `docs/` 下的接入、设计、治理、兼容性文档
- `CONTRIBUTING.md` 中面向协作者的说明

### 2. 保留英文的内容

以下内容保持英文原样，不做意译翻译：

- Maven 模块名
- Java 类型名、方法名、字段名、枚举值
- YAML / properties 配置键
- SQL 表名、列名
- `stepType`、`target`、状态值等公开契约标识

原因很直接：这些内容本身就是用户复制、配置、排查问题时要精确输入的技术标识。

### 3. 文档标题与导航

文档正文以中文为主时，目录和 README 中的文档入口名称也应优先使用中文，避免出现“中文正文 + 英文目录标题”混排。

推荐写法：

- `快速开始`
- `模块架构`
- `定义规范`
- `治理操作`

不要求强制修改文件名。文件名可以继续保持稳定，以减少外部链接和仓库结构波动。

### 4. 示例内容

代码块中的类名、配置项、状态值继续使用英文。

代码块外的说明文字使用中文，例如：

- 用中文解释“什么时候发布 Action”
- 用英文保留 `ActionPublisher`、`SUCCESS`、`action_outbox`

### 5. 新文档准入要求

新增公开文档时，至少满足：

- 标题和说明文字使用中文
- 技术标识保持英文原样
- 第一次出现的关键英文术语，在上下文中给出中文语义
- README 或相关索引文档中的入口名称与正文语言风格一致

## 暂不采用整仓双语的原因

当前仓库仍在快速演进，双语并行会直接带来以下问题：

- 文档更新成本翻倍
- 架构和状态机说明容易出现中英文不一致
- 对当前阶段的主受众没有明显收益

因此第一阶段不要求：

- 每篇文档都提供英文镜像
- README 中同时维护中英文两套完整导航
- 对所有术语做逐句双语对照

## 后续演进条件

当项目满足以下任一条件时，再评估增加英文文档入口：

- 明确开始面向国际开源受众推广
- 已进入稳定发布节奏，文档变更频率显著下降
- 出现持续性的英文使用者反馈或外部贡献需求

届时优先考虑：

- 新增英文版 README 入口
- 为 `quick-start`、`module-selection`、`definition-spec` 提供首批英文镜像

而不是一次性把全部历史文档翻成双语。
